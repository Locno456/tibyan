# تِبْيَان: الجاهزية التجارية — ما نعرفه وما يلزم إثباته

> تقييم تحضيري للجنة، **ليس تصريحاً قانونياً أو ضماناً للربحية**. تحديث 6 أكتوبر 2026. يستند معيار «واقعية التشغيل والاستكمال» (10%) إلى دليل المشارك في `uploads/Participant-Guide.pdf` ص36–40. الرجاء تدقيق العقود والتراخيص لدى أصحاب الحقوق قبل الاستخدام التجاري.

## جواب قصير لسؤال الحكم: هل يمكن استخدامه تجارياً؟

**من الناحية الهندسية يمكن تطوير نموذج خدمة مدفوعة**: الواجهة وAPI خادمية، مفاتيح المزود لا تُرسل إلى العميل، اختيار المصادر قابل للتقييد، ومسار الرجوع متاح. **لكن المنتج ليس جاهزاً للبيع الآن**: لم تُتحقق حقوق إعادة استعمال بيانات القرآن والحديث ومخرجات MCP والبحث الآلي، ولا كلفة الاستدعاءات تحت حمل إنتاجي، ولا الدقة الشرعية بمراجعة بشرية، ولا إجراءات الخصوصية والدعم. رخصة MIT في `package.json` تخص كود المشروع فقط؛ لا تُرخص تلقائياً الملفات المرجعية أو خدمات الأطراف الثالثة.

## سجل الأصول والتراخيص المطلوب توثيقها

| الأصل/الخدمة | الوضع التقني الحالي | ما يجب إثباته قبل البيع |
|---|---|---|
| `data/quran_full.json` | توليد محلي موثق في `scripts/build-quran-data.mjs` من حزمة `quran-json` التي تنسب النص إلى Tanzil/مصحف المدينة | سلسلة المصدر، مطابقة النص، شروط النسخ وإعادة العرض والترجمة، وإسناد الناشر. لا نفترض ترخيصاً تجارياً. |
| `data/hadith_sahihayn.json` | توليد محلي موثق في `scripts/build-hadith-data.mjs` من حزمة `hadith`/SQLite | ترخيص قاعدة البيانات والمتون والتخريج، شروط إعادة التوزيع، وتدقيق عينات مع اختصاصي. |
| مصادر MCP | `lib/sourceRegistry.ts` يتيح مصدر الجمعية ومركز تفسير للقراءة الآلية | شروط واجهاتهم، تخزين/إعادة عرض المخرجات، حدود المعدل، السند والإحالة؛ عدم افتراض أن الوصول التقني إذن تجاري. |
| بحث الدرر السنية | طلبات من الخادم لصفحات بحث محددة في `lib/approvedWebSearch.ts` | سياسة الجلب الآلي والنقل وإعادة العرض؛ إثبات أن مقتطف البحث نفسه يمثل نتيجة حقيقية، لا قائمة تنقل. لا يُعدّ المقتطف حكماً على صحة حديث. |
| Google/سائر مزودي النماذج | يُختار النموذج من كتالوج المزوّد ويتطلب مفتاح خادم | شروط الاستخدام التجاري والخصوصية، أسعار الحساب الفعلية والحصص، الاستبقاء وأماكن معالجة البيانات، خطط الفشل. |
| حساب Supabase | المزامنة اختيارية؛ السياسات موصوفة في `supabase/schema.sql` | إثبات نشر RLS واختبار العزل بين المستخدمين، سياسة احتفاظ وحذف ونسخ احتياطي وإشعار خصوصية. |
| `uploads/` | 3 ملفات رسمية متتبّعة حالياً في تاريخ Git | سؤال المنظم عن الإذن بإعادة نشر الوثائق قبل جعل المستودع عاماً؛ حذفها من آخر التزام لا يمحو تاريخ Git. |

**المالك والإجراء:** يجب أن يجمع صاحب المشروع موافقة/رابط ترخيص مكتوب لكل صف ويحتفظ به خارج Git عند الحاجة، ثم يراجع مختص قانوني وشرعي الاستعمال المقترح. إلى ذلك الحين لا تُعلن الخدمة «مرخصة تجارياً».

## تقدير الكلفة القابل لإعادة الحساب (بلا أسعار مخترعة)

الدخل الشهري المفترض = عدد الأسئلة × سعر السؤال. كلفة النموذج لكل سؤال = عدد استدعاءات النموذج × [(متوسط الرموز الداخلة × سعر المليون الداخل + متوسط الرموز الخارجة × سعر المليون الخارج) / 1,000,000]. تضاف كلفة البحث الخارجية لكل سؤال، ثم كلفة الاستضافة والمصاريف الثابتة الشهرية. **لا تشمل المعادلة تلقائياً الضرائب والمرتجعات وخدمة العملاء ومراجعة المحتوى والمراقبة والتسويق ما لم تُدخل في التكاليف**.

شغّل `npm run estimate:cost -- --questionsPerMonth N --modelCallsPerQuestion N --averageInputTokensPerCall N --averageOutputTokensPerCall N --inputPricePerMillionTokens N --outputPricePerMillionTokens N --externalSearchCostPerQuestion N --monthlyFixedHostingCost N --monthlyOtherFixedCost N --pricePerQuestion N` بعد الحصول على أسعار حقيقية من حسابك وقياس استهلاك فعلي. يرفض البرنامج المدخلات الناقصة وغير الصالحة. `breakEvenQuestions` تقدير رياضي مشروط بهذه الافتراضات، وليس تنبؤاً بالطلب أو الربح. الوحدة النقدية واحدة لجميع الأسعار التي تُدخلها (مثلاً كلها بالريال أو كلها بالدولار).

للاختبار فقط، هذه **أرقام اصطناعية وليست أسعار السوق**:

```bash
npm run estimate:cost -- --questionsPerMonth 1000 --modelCallsPerQuestion 1.2 --averageInputTokensPerCall 1000 --averageOutputTokensPerCall 500 --inputPricePerMillionTokens 2 --outputPricePerMillionTokens 4 --externalSearchCostPerQuestion 0.001 --monthlyFixedHostingCost 20 --monthlyOtherFixedCost 30 --pricePerQuestion 0.1
```

ينتج لهذه الافتراضات وحدها كلفة شهرية `55.8` ودخلاً `100` بالوحدة المختارة؛ لا يُستخدم المثال في تسعير حقيقي. اختبر أيضاً سيناريو طلب منخفض، وسعر أعلى، وإعادة محاولات/فشل المزود، قبل تقرير جدوى أي خطة.

## الحد الأدنى قبل إطلاق مدفوع

1. مراجعة التراخيص والحقوق؛ استبدال أي مصدر لا يسمح بالاستعمال المقترح.
2. تجارب بشرية علمية تعمي مصدر الجواب وتقيس صحة النسبة والامتناع، مع حد قبول معلن قبل التجربة.
3. قياس كلفة وتباطؤ وحصص الاستضافة على أحمال فعلية، ووضع rate limit موزع على API؛ المفتاح الموحد وحده لا يمنع الإنهاك أو الاستغلال.
4. سياسة خصوصية مفهومة: السؤال قد يُرسل إلى مزود النموذج/مصدر خارجي حسب الإعداد، والضيف ليس وعداً بعدم إرسال السؤال إلى مزود خارجي؛ موافقات واضحة على تخزين الحسابات وحذفها.
5. فصل Preview عن Production، ومراقبة لا تسجّل مفاتيح أو نصوصاً حساسة، وخطة استجابة للحوادث ودوران المفاتيح ومسار `TIBYAN_AGENT_ENABLED=false` للرجوع.
