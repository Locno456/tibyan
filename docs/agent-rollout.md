# خطة تفعيل وضع الوكيل تدريجياً

> هذه خطة عمل وليست ادعاءً بأن الميزات أدناه اكتملت أو أن الفوز بالمسابقة مضمون. لا تُغيّر سلوك الإجابة الافتراضي قبل المقارنة والتحقق.

## المرحلة 1 — توافق النماذج (جارٍ)
- [x] تصحيح دور نتيجة الأداة في Gemini: `user` مع `functionResponse` بدلاً من `function`، مع اختبار لهيكل الطلب.
- [x] اختبارات محاكاة للمزود، وفحص TypeScript والبناء.
- [ ] اختبار اتصال حي بنموذج Google عبر تهيئة مفاتيح الخادم ثم `/api/health?probe=1`، واختبار دورة MCP فعلية؛ لا تتوفر مفاتيح في بيئة العمل الحالية.

## المرحلة 2 — مصادر قابلة للتوسع
- [x] سجل خادمي قابل للتوسع لخادمي MCP المعتمدين (`lib/sourceRegistry.ts`) مع رفض تحويل إعدادات الاتصال إلى نطاقات أخرى؛ اختبار إعدادات مصادر إضافية قبل تفعيلها.
- [x] بحث ويب مباشر اختياري في صفحات بحث الدرر السنية (الحديث والتفسير) عبر عناوين ثابتة على الخادم، مع مهلة وحد حجم ورفض إعادة التوجيه. مقتطفات البحث موسومة بأنها غير محققة؛ لا تُعدّ توثيقاً لثبوت حديث. المواقع الإضافية وموصلات البحث الأخرى لم تُراجع بعد.
- [ ] التحقق من وصول كل موصّل وإثبات صلة المادة بالسؤال؛ لا تُحوّل نتيجة بحث عامة إلى دليل تلقائياً.
- [ ] منع طلبات SSRF وعناوين الشبكات الداخلية وإعادة التوجيه والموارد الكبيرة، والتحقق من URL على الخادم عند إضافة أي موقع.

## المرحلة 3 — إعدادات المستخدم والواجهة
- [x] منتقي متعدد للبيانات المحلية وMCP بجانب زر الإرسال؛ يلتزم الخادم بالاختيار. تعطيل MCP في الواجهة إذا أثبت كتالوج النموذج عدم دعمه للأدوات. البحث المباشر في الدرر خيار مستقل لا يحتاج أدوات النموذج.
- [x] «الوضع المتقدم»: عند انعدام الدليل والأدوات يمكن طلب جواب عام من ذاكرة النموذج مع وسم «غير متحقق منها»؛ الافتراضي طلب مصادر. يمتنع عن الاقتباس الشرعي والفتوى الشخصية، ولا يؤكد النسبة دون مصدر. لا يُفعّل الجواب المباشر إذا كان هناك MCP متاح لم يُرجع دليلاً بعد.
- [ ] مواقع مخصصة للباحث المسجل فقط: تحقق خادمي من جلسة المستخدم ونوع الحساب، وفصلها بصرياً عن مصادر المسابقة المعتمدة؛ حدود عدد المواقع والجلب. يعرض الإعداد الآن تنبيهاً بأنها غير مفعّلة، ولا يوجد حقل إدخال مضلل.
- [x] مؤشرات تقدّم حيّة لواجهة المحادثة فقط عبر NDJSON اختياري من `/api/ask`: تصنيف، استرجاع، بحث ويب، اكتشاف MCP، توليد، وفحص — تُرسل فقط عند دخول المسار فعلاً. بقيت عقود JSON و`/api/v1` كما هي؛ المراحل ليست سلسلة تفكير النموذج. زخرفة تفاعلية من Brand Kit تتيح تغيير شكل واحد أثناء الانتظار وتحترم تفضيل تقليل الحركة. يلزم اختبار البث على الاستضافة الحية.

## المرحلة 5 — وكيل إجابة محدود وآمن
- [x] خطة حتمية تحدد وقت إلزام أداة قراءة MCP عند غياب نص محلي موثق (حتى لو وجد مقتطف بحث ويب)، مع حد 2–4 جولات و4–8 استدعاءات حسب المهمة؛ لا بحث للتحية أو مسار الإحالة الشخصية.
- [x] حجب عبارات نسبة الحديث في الشرح المولّد بدلاً من الاعتماد على زخرفة ﴿﴾، مع إبقاء النص المسترجع حرفياً في بطاقة المصدر. نجح المسبار المحلي 4/4؛ ليس ضماناً لكل الصياغات.
- [ ] تدقيق علمي حي للبطاقات المنسوبة، واختبار تكرار توليد Gemini وMCP وتعطل الشبكة؛ لا تقدم مقتطفات البحث دليلاً نهائياً.

## المرحلة 4 — قياس وتحكيم
- [x] قياس الحزمة العلمية خمس مرات مع نطاق النتائج وبصمة القرارات؛ اختبارات انحدار لحالات شخصية مفاجئة، النص القرآني في النمط الافتراضي والصريح، وتعطيل المصادر، ورفض تحويلات الويب/قائمة التنقل/الصفحات الكبيرة. هذه ليست مراجعة للمحتوى المولّد.
- [ ] اختبارات تعطل المزودين ومخرجات أدوات خبيثة على الدورة كاملة (ليس فقط رفض جلب الصفحة)، ومقارنة مباشرة مع نموذج أساسي في نشر حي.
- [ ] مراجعة بشرية مستقلة للإسناد والنصوص الشرعية والرخص وشروط الاستخدام التجاري لكل مصدر.
- [x] خريطة أدلة وفجوات المعايير السبعة وحدود القياس والتكلفة والخصوصية في `docs/judging-readiness.md`؛ لا ضمان للنتيجة. القياسات المالية والترخيص التجاري والمراجعة البشرية ما زالت معلقة.
