## ما قِيس فعلاً وما لم يُقَس

- اختبارات الوحدات والانحدار تستخدم مزوداً ومحركات ويب **محاكاة**؛ لا تثبت استجابة Gemini أو نتائج MCP/الويب من الدومين المنشور.
- `npm run eval:12:repeat` يشغّل التوجيه والاسترجاع والحارس محلياً؛ لا يولّد إجابات ولا يختبر المراجعة الشرعية. يعرض نطاق نتائج كل تشغيل وبصمة قراراتها، ولا يختار أفضل تكرار ليخفي الفشل.
- من الأسئلة المفاجئة في اختبارات الانحدار: طلب حكم طلاق شخصي مع الوضع المباشر، تعطيل مصادر التحقق، وطلب آية بلا بيانات محلية. الاختبارات لا تغطي جميع الصياغات.
- اختبار صفحات البحث يرفض قوائم التنقل وحدها، والردود غير HTML، والتحويلات والصفحات الكبيرة. لا يُفترض أن صفحة بحث هي دليل على صحة الحديث؛ تُعرض مقتطفاتها للمراجعة لا لإثبات النسبة. إذا تغير ترميز صفحة النتائج يفشل البحث بأمان.

## قابلية الاستخدام التجاري — إجابة صادقة للحكم

الكود وحده لا يثبت ترخيصاً تجارياً للمحتوى. يجب قبل أي إطلاق تجاري توثيق أصل وترخيص النص القرآني المحلي، وقاعدة الصحيحين المستخرجة من حزمة `hadith`، وكل مصدر MCP أو موقع بحث، مع التحقق من شروط إعادة العرض والتخزين والتحميل الآلي، وسياسات مزودي النماذج والتكلفة والخصوصية. إلى حين إتمام ذلك: **الجدوى التقنية ممكنة مبدئياً؛ الإذن القانوني والتكلفة والاستدامة غير مثبتة**. لا تُقدّم هذه الوثيقة بديلاً عن مراجعة قانونية أو علمية مختصة.

## قائمة تحقق يوم العرض

1. اختبر الموقع المنشور بمفتاح مزود خادمي حقيقي دون كشف المفتاح، وسجّل نجاح/فشل توليد Gemini وMCP `tools/call` ونتائج الويب الفعلية، لا `tools/list` وحده.
2. اطلب مراجعة بشرية مستقلة لعيّنة عشوائية من الإجابات والأسانيد والروابط وحالات الامتناع؛ دوّن الأخطاء وكيف عولجت.
3. شغّل `npm test && npm run build && npm run eval:12:repeat` ووثّق التاريخ والبيئة. لا تعرض 46/46 اختباراً كقياس لصحة الأحكام الشرعية.
4. اختبر الحدود: تعطل مزود النموذج، مهلة MCP، تغيّر HTML، إدخال تعليمات خبيثة في النتائج، نفاد الرصيد، ومعدل الطلبات.
5. تحقق من متطلبات النشر العامة وحقوق الوثائق الرسمية داخل `uploads/` قبل تغيير رؤية المستودع؛ افصل الملفات التي لا يجوز نشرها واستبدل أي مفتاح سبق تسريبه.
