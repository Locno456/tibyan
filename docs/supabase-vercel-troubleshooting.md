# لماذا يظهر تنبيه Supabase على Vercel بعد ضبط المتغيرات؟

تنبيه «لم يتلقّ المتصفح إعداد Supabase» يعني أن التطبيق لم يستطع إنشاء عميل Supabase بعد تحميله في المتصفح. لا يمكن حل غياب المتغيرات بتشغيل SQL وحده: مفاتيح `NEXT_PUBLIC_*` تُضمَّن في حزمة المتصفح عند **البناء**.

1. تحقق في Vercel → Project → Settings → Environment Variables من الاسمين حرفياً: `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY`. لا تستخدم المفتاح السري `service_role`. يجب أن تكون القيم غير فارغة، URL يبدأ بـ`https://` ويشير إلى مشروعك في Supabase، ولا تُضف أقواساً أو أسماء متغيرات في حقل القيمة.
2. تحقق من النطاق: موقع `https://tibyan-demo.vercel.app/` يستعمل نشر **Production**؛ متغيرات Preview فقط لا تصل إليه. اختر Production، وأضف Preview إذا كنت تختبر رابط معاينة منفصلاً.
3. من Deployments أعد **Redeploy** لأحدث نشر بعد إضافة المتغيرات (إن شككت في التخزين المؤقت أعد البناء بدون build cache). التعديل لا يغيّر حزم JavaScript التي سبق بناؤها. تأكد من أن الـdeployment تابع للفرع والتحديث المطلوبين ومن المشروع نفسه الذي أضفت فيه المتغيرات.
4. افتح `/account` في نافذة خاصة وانتظر انتهاء التحقق من الجلسة؛ إن بقي التحذير بعد التحميل افحص Console لأخطاء تكوين URL أو مفاتيح Supabase. لا تلصق المفتاح في تذكرة دعم عامة أو دردشة.
5. إذا اختفى التحذير لكن تسجيل الحساب أو المزامنة يفشلان، شغّل `supabase/schema.sql` ثم `supabase/shared-conversations.sql` في **مشروع Supabase نفسه**، واضبط Auth Site URL وروابط redirect. هذه خطوة مستقلة عن وصول المتغيرات إلى المتصفح.

تنبيه تسجيل الدخول يظهر الآن **بعد اكتمال تهيئة الجلسة على المتصفح** حتى لا يظهر خطأً لحظياً أثناء العرض الخادمي SSR قبل تحميل إعدادات العميل. هذا لا يصلح متغيراً مفقوداً في نشر Vercel؛ تشخيص Vercel وإعادة النشر مطلوبان فعلاً.
