## 2. الأسباب الأربعة (مرتّبة حسب الأثر)

### السبب 1 — لا يوجد مفتاح، فالـ«ذكاء» جدول بحث من 4 كلمات
لم يكن في المستودع سوى `.env.example` (تأكد: `ls -la .env*` → ملف واحد).
بلا `GEMINI_API_KEY` يسلك `app/api/ask/route.ts` فرع `getMockExplanation()`، وهو مطابقة كلمات مفتاحية فقط:

```ts
if (q.includes("كعبة")) …  if (q.includes("قرآن") && …) …  if (q.includes("سيف")) …  if (q.includes("توحيد")) …
return personaExplanations["default"]   // ← أي سؤال آخر يسقط هنا
```

`"default"` فقرة ثابتة تتحدث **عن النظام** («هذا سؤال مهم. بناء على المصادر المعتمدة نقدم شرحاً موثقاً…») لا عن سؤال السائل — وهذا بالضبط الإحساس بأن الرد «غير تفاعلي».

### السبب 2 — النموذج الافتراضي موقوف من Google منذ أكثر من سنة
`lib/gemini.ts` كان يضبط `flashLite: "gemini-1.5-flash-8b"`.
سجل Google الرسمي: **«September 29, 2025 — The following Gemini 1.5 models are now shut down: gemini-1.5-pro, gemini-1.5-flash-8b, gemini-1.5-flash»** ([ai.google.dev/gemini-api/docs/changelog](https://ai.google.dev/gemini-api/docs/changelog)).

→ **حتى لو أضفت المفتاح، كان الاستدعاء سيفشل**، ويقع في `catch` فيرجع إلى `getFallbackExplanation()` — نفس النصوص المعلّبة، مع اختلاف بسيط في شارة صغيرة. فشل صامت تماماً.

النماذج السارية في أكتوبر 2026: `gemini-3.5-flash-lite` (الأسرع/الأرخص) · `gemini-3.1-flash-lite` · `gemini-3.8-flash`.

### السبب 3 — لا سياق محادثة يُرسل إطلاقاً
`app/page.tsx:122` كان يرسل `{ question, persona }` فقط. أي أن النموذج — لو عمل — يرى سؤالاً واحداً معزولاً بلا ذاكرة للمحادثة، فلا يستطيع أن «يبني على ما قلته» ولا أن يتابع. هذه هي «اللاتفاعلية» حتى مع نموذج يعمل.

### السبب 4 — الفشل لا يظهر للمستخدم
مصدر الشرح كان يظهر فقط في شارة مقطوعة إلى 34 حرفاً (`ChatMessage.tsx:211`). لا لافتة ولا تحذير.

## 4. كيف تتأكد أنه يعمل — أمر واحد

```bash
curl -s "localhost:3000/api/health?probe=1"
```

`verdict` يأخذ إحدى أربع قيم:

| القيمة | المعنى | الإجراء |
|---|---|---|
| `working` | النموذج يستجيب فعلاً (مع `reply` و`latencyMs`) | جاهز |
| `broken` | المفتاح موجود لكن الاستدعاء يفشل — اقرأ `liveProbe.error` | غالباً نموذج موقوف أو مفتاح خاطئ أو تجاوز حصة |
| `unverified` | المفتاح موجود ولم يُجرَ استدعاء | أضف `?probe=1` |
| `offline` | لا مفتاح مزود — المسارات القرآنية المحلية المحددة فقط لا تحتاج نموذجاً، والأسئلة الأخرى قد تمتنع | أضف مفتاح مزود خادم إذا احتجت التوليد

### نتائج الفحص الفعلية بعد الإصلاح

| الإعداد | `verdict` |
|---|---|
| بلا مفتاح | `offline — المسارات القرآنية المحلية المحددة فقط لا تحتاج نموذجاً؛ لا تُستخدم إجابة ثابتة كأساس بديل` |
| مفتاح + `gemini-1.5-flash-8b` | `broken` · `liveProbe.error`: «النموذج "gemini-1.5-flash-8b" أوقفته Google (نماذج 1.5 أُوقفت في 2025-09-29). حدّث GEMINI_MODEL إلى gemini-3.5-flash-lite» |
| النموذج الافتراضي الجديد | `gemini-3.5-flash-lite` · `retired: false` |

وفحص `buildTibyanPrompt` مباشرةً:

```
بدون سجل — يحتوي سياق محادثة؟ false
مع سجل   — يحتوي سياق محادثة؟ true
مع سجل   — السؤال السابق ظاهر؟ true
مع سجل   — رد تِبْيَان السابق ظاهر؟ true
مع سجل   — السؤال الحالي مُعلَّم؟ true
نمط حواري في systemInstruction؟ true
```


اختيار النموذج يُجرى من كتالوج المزود؛ لا تفترض اسم نموذج أو صلاحية مفتاح قبل هذا الفحص.

ثم جرّب سؤالين متتاليين — الثاني يجب أن يبني على الأول بدل إعادة التعريف.

## 6. ما لم يُختبر من هذه البيئة

**الاستدعاء الحي الناجح لـ Gemini لم يُختبر** — الـ sandbox بلا اتصال شبكي صادر (كل محاولات `curl` الخارجية أعادت `000`).
المُختبَر فعلياً: اكتشاف غياب المفتاح، اكتشاف النموذج الموقوف ورمي الخطأ قبل أي طلب شبكة (`latencyMs: 1`)، تمرير `history` في الـ prompt، وقبوله عبر HTTP، ومسار القالب المحلي الصريح.
عند تشغيل `?probe=1` على جهازك بمفتاح صحيح سترى `working` أو السبب الحقيقي للفشل.

## 8. تحديث التنفيذ متعدد المزودات — 2026-10-06

أضيفت موصلات خادمية إلى Google AI Studio/Gemini وAnthropic وOpenAI وOpenRouter وGroq وZ.ai، مع Mistral وDeepSeek كخيارين إضافيين. واجهة `/api/models` تعرض المزودات التي لها مفاتيح خادم فقط، وتجلب فهرس النماذج من API المزود؛ نافذة السياق لا تظهر إلا إذا أعادها الحقل الفعلي. اختيار النموذج يمر إلى `/api/ask`، واختبار «اختبار» ينفّذ توليداً قصيراً عند ضغط المستخدم. **لم يُختبر أي مزود بمفتاح حي؛ واكتشاف نماذج Z.ai خصوصاً ما زال بحاجة إلى تحقق من حساب فعلي.**

**حدود التحقق الحالية:** لا يوجد في هذا السجل نجاح حي موثّق لاستدعاء أي مزود أو `MCP tools/call`. `GET /api/health?probe=1` يجري اختبار توليد فعلياً، و`GET /api/health?mcp=1` يفحص `initialize` و`tools/list` فقط؛ نتيجة `tools/list` ليست إثباتاً على نجاح استدعاء أداة. لم يُجرَ أي نشر إلى Vercel.

**تغيير fallback:** لم تعد الاستجابات غير المدعومة تستخدم قوالب بينات ثابتة وكأنها إجابة مولّدة. من دون مزود مهيأ أو عند فشل الاتصال، يصرّح المسار بالعجز/الامتناع؛ طلب الآية المباشر والتحية وبعض المسارات المحددة تعمل محلياً.

**سلوك الوكيل والأدلة الطويلة — 2026-10-06:** يكتشف الخادم مخططات أدوات MCP للقراءة فقط ديناميكياً. عند غياب الدليل المحلي، يطلب تقنياً استدعاء أداة أولاً عبر Gemini وAnthropic وواجهات OpenAI-compatible؛ تبقى النتائج خاضعة لفحص الصلة، وينتهي النقص بامتناع. اختبارات الأدوات في هذه البيئة اصطناعية، ولم تنجح أدوات MCP الحية في جولة الفحص. في المحادثة يظهر الحديث الطويل كمقتطف قصير، وتبقى مادته الكاملة في نافذة «تفاصيل المصادر»؛ نص القرآن لا يُختصر أو يُعدّل.

**فحص البناء والاعتمادات — 2026-10-06:** اجتاز البناء على Next.js `15.5.24`، ونجحت الاختبارات `24/24` وفحص TypeScript. تدقيق اعتماديات الإنتاج (`npm audit --omit=dev`) بلا ثغرات. التدقيق الكامل يسجل 7 ثغرات في اعتماديات التطوير (5 عالية و2 متوسطة)، ضمن سلسلة Tailwind CSS 3؛ لم يُفرض انتقال Tailwind 4 لأنه ترحيل رئيسي غير متحقق من أثره على الهوية والأنماط.

**المراجع الفنية للتنفيذ:**
- `/api/models` — جلب كتالوج المزودات المهيأة من جهة الخادم.
- `/api/models/probe` — اختبار توليد فعلي للنموذج الذي اختاره المستخدم.
- `/api/health?probe=1` — اختبار اتصال للمزود الافتراضي أو المحدد.
- `/api/health?mcp=1` — فحص اكتشاف MCP فقط؛ لا يستدعي أداة قراءة.
